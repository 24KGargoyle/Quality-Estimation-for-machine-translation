# Database

Plain PostgreSQL 16 — no extensions required. Schema defined in
`app/backend/src/meeting_intel/db/models.py`, migrations in `app/backend/alembic/versions/`.

## Entities

| Table | Purpose | Key columns / indexes |
|---|---|---|
| `tenants` | Tenant isolation boundary | unique `ms_tenant_id` |
| `users` | Per-tenant users | unique `(tenant_id, email)`, unique `ms_object_id`, index on `tenant_id`, `email` |
| `meetings` | Loaded Teams meetings | unique `(tenant_id, ms_meeting_id)`, index on `tenant_id`, `status` |
| `meeting_participants` | Authorization + speaker roster | index on `(meeting_id, user_id)` |
| `meeting_transcripts` | One raw transcript per meeting | unique `meeting_id` |
| `transcript_chunks` | Chunked, embedded transcript text | index on `meeting_id`, `speaker`, `(meeting_id, speaker)`; generated `tsv` column + GIN index for keyword search; `embedding` stored as plain JSON — cosine similarity for semantic search is computed in Python, not via a DB-side vector index (see docs/RAG_ARCHITECTURE.md) |
| `conversations` | Private AI chat threads | index on `tenant_id`, `user_id`, `meeting_id` |
| `conversation_members` | Reserved for future shared private chats | unique `(conversation_id, user_id)` |
| `messages` | Every chat/group message | polymorphic parent: exactly one of `conversation_id`/`group_id` set (`CHECK` constraint); index on both |
| `ai_responses` | Metadata for one assistant message | unique `message_id` |
| `ai_sources` | Citations for one AI response | index on `ai_response_id`, FK to `transcript_chunks` |
| `feedback` | 👍/👎 + reason | unique `(message_id, user_id)`, index on `message_id`, `user_id` |
| `groups` | Internal or Teams-mapped groups | index on `tenant_id` |
| `group_members` | Membership + AI-participant flag | unique `(group_id, user_id)` |
| `discussions` | A shared-context thread inside a group | index on `group_id` |
| `decisions` | Captured decisions (always human-confirmed) | index on `group_id` |
| `action_items` | Extracted/edited action items | index on `group_id` |
| `teams_mappings` | Internal group ↔ Teams chat/channel | index on `tenant_id`, unique `group_id` |
| `audit_log` | Security/audit trail | index on `(tenant_id, created_at)` |

## Migrations

Two migrations under `app/backend/alembic/versions/`:
1. `initial schema` — all tables above (autogenerated from the models).
2. `full-text search column + GIN index` — adds the generated `tsv` column on
   `transcript_chunks` and its GIN index for keyword search.

Run migrations: `alembic upgrade head` (from `app/backend`, with `DATABASE_URL` set).

## Tenant isolation

Every user-facing query filters by `tenant_id` (directly, or transitively via a `meeting_id`/
`group_id` that itself belongs to the tenant) — see `security/authz.py`. A row's existence is
never revealed to a caller outside its tenant (a cross-tenant lookup returns `404`, not `403`).
