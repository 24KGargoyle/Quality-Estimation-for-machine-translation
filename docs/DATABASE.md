# Database

SQLite (local development/tests, via the async `aiosqlite` driver) or Azure SQL Database
(production, via `AZURE_SQL_CONNECTION_STRING`) — see `docs/AZURE_SETUP.md`. **No PostgreSQL
dependency anywhere in this app** — see `docs/MIGRATION_FROM_POSTGRES.md` for what changed and
why. Schema defined in `app/backend/src/meeting_intel/db/models.py`, migrations in
`app/backend/alembic/versions/`.

Transcript chunks and their embeddings are **not** stored in this database — they live in the
`SearchProvider` abstraction (`retrieval/search_provider.py`; see `docs/RAG_ARCHITECTURE.md`).
This relational store holds only application/transactional data.

## Entities

| Table | Purpose | Key columns / indexes |
|---|---|---|
| `tenants` | Tenant isolation boundary | unique `ms_tenant_id` |
| `users` | Per-tenant users | unique `(tenant_id, email)`, unique `ms_object_id`, index on `tenant_id`, `email` |
| `meetings` | Loaded Teams meetings | unique `(tenant_id, ms_meeting_id)`, index on `tenant_id`, `status` |
| `meeting_participants` | Authorization + speaker roster | index on `(meeting_id, user_id)` |
| `meeting_transcripts` | One raw transcript per meeting | unique `meeting_id` |
| `conversations` | Private AI chat threads | index on `tenant_id`, `user_id`, `meeting_id` |
| `conversation_members` | Reserved for future shared private chats | unique `(conversation_id, user_id)` |
| `messages` | Every chat/group message | polymorphic parent: exactly one of `conversation_id`/`group_id` set (`CHECK` constraint); index on both |
| `ai_responses` | Metadata for one assistant message | unique `message_id` |
| `ai_sources` | Citations for one AI response | index on `ai_response_id`; `chunk_id` is a plain string identifying a chunk in the `SearchProvider` (no FK — the chunk itself lives outside this database) |
| `feedback` | 👍/👎 + reason | unique `(message_id, user_id)`, index on `message_id`, `user_id` |
| `groups` | Internal or Teams-mapped groups | index on `tenant_id` |
| `group_members` | Membership + AI-participant flag | unique `(group_id, user_id)` |
| `discussions` | A shared-context thread inside a group | index on `group_id` |
| `decisions` | Captured decisions (always human-confirmed) | index on `group_id` |
| `action_items` | Extracted/edited action items | index on `group_id` |
| `teams_mappings` | Internal group ↔ Teams chat/channel | index on `tenant_id`, unique `group_id` |
| `audit_log` | Security/audit trail | index on `(tenant_id, created_at)` |
| `oauth_states` | Server-issued, single-use Entra OAuth `state` values (CSRF protection) | primary key `state`, `expires_at` |
| `revoked_tokens` | JWT `jti`s revoked by logout | primary key `jti`, `expires_at` |

## Migrations

Migrations under `app/backend/alembic/versions/`:
1. `initial schema` — all tables above (autogenerated from the models; portable across SQLite
   and Azure SQL — no PostgreSQL-specific types, defaults, or raw SQL).

Run migrations: `alembic upgrade head` (from `app/backend`, with `DATABASE_URL` or
`AZURE_SQL_CONNECTION_STRING` set). The SQLite default's parent directory (`./data/`) is created
automatically by `ensure_sqlite_parent_dir()` (`config.py`), called from both `db/session.py` and
`alembic/env.py`, so a fresh clone's first `alembic upgrade head` just works with zero setup.

A prior migration that added a PostgreSQL `tsvector`/GIN full-text-search column has been
**removed** — full-text/keyword search now happens in the `SearchProvider` (Azure AI Search or
the in-memory dev provider), not in this database. See `docs/MIGRATION_FROM_POSTGRES.md`.

## Tenant isolation

Every user-facing query filters by `tenant_id` (directly, or transitively via a `meeting_id`/
`group_id` that itself belongs to the tenant) — see `security/authz.py`. A row's existence is
never revealed to a caller outside its tenant (a cross-tenant lookup returns `404`, not `403`).
This holds regardless of the underlying SQL dialect (SQLite locally, Azure SQL in production) —
authorization is enforced in application code, not by anything dialect-specific.
